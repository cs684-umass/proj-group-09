# Evaluation: Guard Behavior and Trust Score Analysis

This folder contains log‑level evaluation and visualization of the guard decision mechanism using outputs from evaluate.py. The analysis is based solely on the recorded audit logs (defense_audit_log.json) and does not rely on rerunning the full pipeline or accessing external APIs.

The goal of this evaluation is to audit guard behavior, trust score usage, and rejection patterns under adversarial or sensitive queries.

---

## Data Source

Input file: defense_audit_log.json  
Total entries analyzed: 151

Each log entry contains:
- trust_score
- should_append (APPEND vs REJECT decision)
- reasons (guard explanations and diagnostics)

---

## Visualizations Overview

1. Trust Score Distribution  
File: plots/trust_score_histogram.png  
Generated by: plot_evaluation1.py

This histogram shows the overall distribution of trust scores across all evaluated queries.  
A vertical dashed line indicates the mean trust score (0.70).

Key observations:
- Trust scores are highly discrete, clustering around ~0.3, ~0.4, and 1.0.
- The mean is pulled upward by a large mass of high‑trust accepted queries.
- The distribution suggests trust scores are not continuous but bucketed or threshold‑driven.

---

2. Action Distribution: ACCEPT vs REJECT  
File: plots/action_pie_chart.png  
Generated by: plot_evaluation1.py

This pie chart shows the proportion of guard decisions.

Results:
- APPEND: 82 (54.3%)  
- REJECT: 69 (45.7%)

Interpretation:
The guard is selective but not overly restrictive, rejecting nearly half of evaluated inputs.  
This balance is consistent with a conservative filtering strategy rather than blanket rejection.

---

3. Top Rejection Reasons (Primary Reason Only)  
File: plots/rejection_reason_bar.png  
Generated by: plot_evaluation1.py

This bar chart shows the primary rejection reason (first reason recorded) for rejected queries.

Findings:
- All rejections are attributed to “Guard rejected” as the primary cause.
- Secondary diagnostics (e.g., answer mismatch) appear in logs but are not used as the primary decision trigger.

Implication:
The guard operates as a single‑gate decision mechanism, with downstream checks providing justification rather than control.

---

4. Trust Score Distribution by Guard Decision  
File: plots_optional/trust_by_decision.png  
Generated by: plot_evaluation2.py

This plot overlays trust score distributions for:
- APPEND decisions  
- REJECT decisions

Key observations:
- APPEND decisions occur almost exclusively at trust = 1.0.
- REJECT decisions cluster tightly around trust ≈ 0.3–0.4.
- There is no overlap between low‑trust accepted queries or high‑trust rejected queries.

Interpretation:
This plot provides the clearest evidence that:  
- Guard decisions are strongly and consistently aligned with trust scores.  
- The system enforces clean threshold separation without contradictory behavior.

---

## Diagnostic Checks (Log‑Level Only)

The following conservative indicators were computed without claiming ground‑truth correctness:

- Accepted entries with trust < 0.5: 0
- Rejected entries with trust > 0.8: 0

This suggests:
- No obvious false positives or false negatives at the trust‑policy level.
- The guard behaves consistently with its internal confidence signals.

---

## Scope and Limitations

- This evaluation is log‑level only and does not re‑execute model inference.
- Rejection reasons are analyzed as recorded, without semantic re‑classification.
- No per‑scenario or per‑attack breakdown is included.

These analyses are sufficient for:
- Guard auditing  
- Decision transparency  
- Threshold behavior verification

## Summary

This evaluation demonstrates that the guard:
- Applies strict trust‑based decision boundaries  
- Rejects low‑trust queries consistently  
- Does not exhibit contradictory accept/reject behavior  
- Provides stable and interpretable audit logs  

The included plots offer a concise and transparent view of guard performance without requiring full pipeline execution.
