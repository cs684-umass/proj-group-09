# proj-group-09

## Repository Structure

```
proj-group-XX/
│
├── assignment-1/
│   ├── code/                  # all scripts, notebooks, or source code files
│   │   └── ... 
│   ├── README.md              # required write-up: design choice, results, etc.
│
├── assignment-2/
│   ├── code/
│   │   └── ...
│   ├── README.md
│
├── assignment-3/
│   └── ... (same structure)
│
└── README.md                  # optional top-level README describing repo structure
```

---

## Instructions

1. **Create a folder per assignment**  
   - Use the naming convention: `assignment-1`, `assignment-2`, …  

2. **Upload Code + README.md**  
   - Place all scripts, notebooks, or other code inside the `code/` folder.  
   - Add a `README.md` in each assignment folder with:  
     - setup requirements  
     - how to run the code  
     - expected results  

---

## README Guidelines (for every assignment)

Each assignment folder must include a `README.md`.  
Keep it short but complete — aim for 1–2 pages max.  

1. **Dataset** (mainly for Assignment 1 and whenever you create data)  
   - What does your dataset represent (use case)?  
   - How big is it (#samples, labels)?  
   - How did you generate or collect it?  
   - Provide 1–2 small examples.  

2. **Method / Attack**  
   - What approach did you try (design choices, threat model if relevant)?  
   - How did you implement it (tools, key steps)?  

3. **Results**  
   - Main metrics or outcomes (tables/figures if useful).  
   - 1–2 sentences explaining what the results mean.  

4. **Implications**  
   - What risks, weaknesses, or lessons do these results show for your project?  
   - Any key limitation or next step.  

---

👉 That’s it: **Dataset → Method → Results → Implications.**  
Enough structure to make reports consistent, but still lightweight and flexible across assignments.
